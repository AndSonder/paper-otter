# 逻辑对抗检查

这一步发生在完整 `logic-draft.md` 写完之后、中文润色和首次阅读检查之前。使用一个未参与写作的新上下文。它只能看到目标读者背景、用户最初的阅读目标和实际逻辑稿；不能看到 `evidence.md`、作者提纲、预期答案、旧稿或其他评语，也不联网补写正文。

让审稿人先独立重建文章的核心问题、因果链和结论范围，然后只报告会改变读者判断的缺口：

1. 哪个合理但错误的结论仍可能从正文推出？指出产生误读的具体段落，并给出能区分两种理解的最小反例、算例或操作轨迹应回答什么问题；不代写该例子。
2. 哪个结论的适用范围被写宽了？说明改变哪个条件后结论会失效，或哪些事实只能支持较窄的说法。
3. 哪一步虽然技术上正确，却没有帮助目标读者完成原始判断？说明删去或后置后会不会破坏后文。
4. 读者面对一个新情形时，还缺少哪一步才能自己判断？优先检查公式到行为、局部机制到训练轨迹、理论量到实现量之间的迁移。

报告保存为 `logic-review.md`。不要打总分，不按固定数量凑问题；没有实质缺口时明确说明。作者逐项判断反馈，必要时回到原始来源或重做推导，再把修订落实到 `reader-draft.md`，并在 `revision-notes.md` 记录采纳、拒绝及理由。逻辑审稿人不负责中文顺滑度，后续新上下文读者仍按 `reader-review.md` 做第一次完整阅读。
