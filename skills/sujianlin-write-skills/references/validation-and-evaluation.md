# 定稿验证与 skill 评估

作者定稿时读第一段；开发评估 skill 时再读第二段。

重读实际最终稿，对照来源检查本轮新增的事实、因果、公式和图文关系。若独立读者之后又修改了正文，先比较 `reader-draft.md` 与 `article.md`，逐个阅读所有改动块及其前后段落：确认补入的新解释没有挤断原问题，删除旧句后没有留下重复公式、半段结论或失去指代的过渡。这个检查只针对最终改动，不重新泛读一遍后凭印象放行。

Markdown 可运行 `python3 scripts/check_reading.py <文章路径>`。完整数学稿还要用目标数学引擎解析；已有本地 KaTeX 时加 `--katex-module <KaTeX包目录>`。缺包且可安装时用临时目录，不改用户项目依赖。脚本已用 KaTeX 0.16.22 验证；启发式检查不是解析替代，解析通过也不是数学正确、页面排版或可读性的证明。若脚本报告疑似漏写反斜杠的 TeX 命令，或用普通括号包住的数学表达式，逐项判断并修复后重新运行；不能因为 KaTeX 没把该段识别成数学就视为通过。编号、缩写和自然语言括注可能误报，核对后可保留并在验证记录说明。

用户要求评估 skill 时，使用固定题目、输入和读者定位，给新上下文作者冻结 skill 与原始资料，不给旧稿、参考原文、评语或预期修复。作者可自主多轮修订，提交最终稿后封存。外部评语用于改 skill，再由新作者重跑；主线程不能改稿后当作 skill 独立产出。比较全文与同题参考的具体阅读体验，不自报数字高分，不把开发题称为未见测试。原论文迁移及实际图文阅读另行验证。

研究来源说明见 [references/research-basis.md](research-basis.md)，写作时不必加载博客语料。
