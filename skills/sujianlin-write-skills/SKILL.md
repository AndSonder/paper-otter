# 原创中文论文讲解

目标读者愿意认真读，但不应替文章补关键推理。沿用项目名称，学习技术解释方法，写原创文章。

## 作者上下文

完整论文阅读稿必须由不继承主线程历史的新作者 agent 执笔。只给作者原始阅读目标、读者背景、论文原文或固定版本、可核查证据和本 skill；不要给它主线程已有的摘要、讲解、推荐文案、用户对旧稿的批评或预设结论。作者从 evidence 与 logic draft 开始，而不是修补一篇先写好的短稿。后续逻辑审查和首次阅读检查再分别使用两个新的独立上下文；作者根据报告修订。短段落润色不受此限制。


## 写作与修订

先明确读者已有知识和读完要能解决的问题。阅读原始资料，保存简短证据笔记，然后写出完整逻辑稿。轮数由实际问题决定：可以先理顺逻辑，再润色中文，也可以回退重写；不要求首稿完成。

完整论文阅读稿在逻辑稿完成后、中文润色前，使用一个新上下文做逻辑对抗检查，具体按 [references/logic-adversary.md](references/logic-adversary.md)。审稿人只寻找会改变读者判断的缺失反例、外推边界和无效旁支，不代写文章。作者先处理这份报告，再写送读稿；它不能取代后面的首次阅读检查。

用户要认真研读论文时，先从原始阅读目标中找出最值得追究的核心问题，把篇幅用于展开它的答案及其后果。理论论文解释关键推导和成立条件；实验论文解释研究设计、测量、对照与证据强度；系统论文解释数据流、依赖与性能边界；综述论文解释分类依据、共识和争议。不要在读者刚会复述定义时就转去罗列相关工作。旁支只有在帮助回答主问题时才展开。深度不由术语数、证明长度或覆盖面决定，也不要求一篇文章包办整个领域。用户没有字数限制时，不自行给研读稿设短文上限；阅读时间用于取舍内容，不靠凑字数填满。

正文要把一个问题解释明白，而不是展示作者完成了多少检查。用读者已懂的量和关系推进；某种证明虽正确，若绕进一套无助于理解当前问题的新对象，就应换更直接的解释。必要推理不能靠缩短篇幅省掉。无需提交规定格式的逆向提纲或路线比较；修改记录只记实际改了什么、为什么。

完整论文阅读稿使用一个新上下文读者，具体按 [references/reader-review.md](references/reader-review.md)。读者只看正文、背景和原始阅读目标，不看提纲、证据、预期答案或作者希望找到的问题。作者根据实际反馈自主修订，读者不代写。工具不支持子 agent 时明确只能自查，不能假称独立阅读；短段落修改无需额外读者。

完整文章保存 `logic-draft.md`、`logic-review.md`、实际送读的 `reader-draft.md`、`reader-report.md`、最终 `article.md`，以及简短的 `revision-notes.md` 和 `evidence.md`。阶段文件用于追溯，用户通常只读最终正文。短段落润色直接交付改稿，除非用户要求，不生成这些阶段文件，也不套用完整文章的送读流程。修改后核对实际保存稿，尤其检查本轮新加的推理、事实和图注；模型读者通过不等于真实用户满意。

由 Paper Otter 调用时，必须通过 `paperctl.py writing-begin` 和逐阶段 `writing-record` 建立有序哈希链；不得手写 `writing.json` 或 `writing-workflow.json`。最后一次登记 `article` 后，脚本生成 version 2 completion manifest。修改已登记的任一阶段文件都会使发布失败，必须明确重启写作流程；没有完成标记的正文不会被网站发布。

由每日推荐框架调用时，以上文件保存在 `.paper-daily/papers/<paper-id>/`，不得加入框架仓库。

正文引用同目录图片时使用 `assets/<文件名>` 相对路径，由 Paper Otter 发布时转换为网站路径；不要在私有正文中写死 `/local/papers/...`。

## 核心要求

段落接住前面留下的问题，新概念从读者已经理解的关系引出。必要推理不能让读者代补，特例不能冒充一般证明。中文说清对象、动作与因果；局部公式正确不等于全文容易读。

事实、引文、数据与实验回到原始来源核验，严格结论、相关关系、因果主张、近似和算例分清。正文保留决定判断的条件，核查过程放入证据笔记。图要帮助读者完成具体观察，并在实际阅读尺寸下检查；有图文件不等于图文解释成立。

## 按任务和阶段读取

以下资料由本入口直接定位，不必全部预先加载；修订可回到此前阶段。

- 写数学推导或机制讲解的逻辑稿前，读 [组织推理](references/reasoning.md)。系统论文涉及数据流、等待或执行顺序时，同时读 [机制解释示例](references/explanation-patterns.md)。
- 提取论文证据、规划配图时，读 [来源与图文](references/sources-and-visuals.md)。处理 arXiv 原图时再读 [源码与图片](references/arxiv-source-figures.md)。
- 逻辑稿完成后、写送读稿前，读 [逻辑对抗检查](references/logic-adversary.md)，把原始阅读目标、读者背景和 `logic-draft.md` 交给新上下文；不提供证据笔记或预期答案。
- 修订中文或安排延伸阅读时，读 [中文与延伸](references/language-and-extensions.md)；需要句子或图文修复示例时，读 [示例](references/chinese-and-figures.md)。
- 完整稿送独立读者前，读 [读者检查](references/reader-review.md)。只提供原始目标、背景和实际正文，不泄漏作者预期。
- 定稿时读 [验证](references/validation-and-evaluation.md) 的作者部分；评估 skill 时再读其评估部分。

研究依据见 [来源说明](references/research-basis.md)，普通写作不需要读取博客语料。
