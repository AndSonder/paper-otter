# 推荐流程

## 1. 形成当天检索意图

从当前目标中选一个主问题，再加入一个邻近问题用于探索。结合历史记录排除近期已读、明确拒绝和高度重复的论文。默认候选池 8–20 篇，不能只比较搜索结果前三名。

同时确定这篇论文最合适的阅读方式。它由当天问题和论文类型决定，不从画像中套用固定模板；例如理论论文可能需要推导，实证论文需要研究设计判断，系统论文需要机制与实现边界。

候选进入排序前，逐篇执行 [来源与学习价值门槛](source-quality.md)。没有通过门槛的候选不能因为主题相似或发布时间新而成为主读。

## 2. 建立候选证据卡

每篇至少记录：稳定 ID、标题、日期、原始链接、摘要、核心主张、实验环境、发表或报告状态、来源组织、准入角色、与目标的连接、阅读成本、可能失配点和来源时间。事实与模型推断分开写。

## 3. 语义排序

逐项比较而不是先拍一个总分：

- 当前问题的直接帮助程度；
- 相对读者已有知识的新信息；
- 通过准入后，哪篇能带来最多可迁移的新判断；
- 阅读成本是否匹配当天预算；
- 与最近推荐是否重复；
- 行为反馈是否支持继续推荐这一主题和深度。

最后才生成仅用于排序的内部分值和置信度。来源声望不得直接折算成总分；它只参与来源核验和证据可信度判断。保存各维判断与淘汰原因，避免无法审计的“LLM 觉得好”。

## 4. 控制探索

默认约 80% 贴合已知目标、20% 邻近探索。连续三次未打开某类候选时暂停一周；显式拒绝立即暂停相同窄主题，除非用户说明只是时机不合适。探索项必须说明为什么值得偏离主线。

## 5. 输出与学习

主读推荐只承诺一篇。两篇备选用于主读失配，不同时制造阅读债务。次日读取曝光、打开、有效时长、进度、点赞、收藏、不感兴趣原因和用户文字反馈，更新的是画像中的证据与置信度，而不是永久标签。
